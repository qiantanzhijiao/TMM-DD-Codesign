# UniDD

A differentiable, Poynting-consistent transfer-matrix and drift-diffusion
kernel for co-design of thin-film solar cells.

The code computes a wavelength-resolved optical generation rate from a fully
coherent multilayer stack and solves the coupled Poisson / electron / hole
continuity equations on the same computational graph. Derivatives of any
figure of merit with respect to layer thickness, complex refractive index and
bulk lifetime come from the implicit function theorem, through one transposed
Jacobian solve of the converged drift-diffusion state. No surrogate model and
no interpolation between the optical and electrical grids are involved.

## Install

Python 3.11 or newer is recommended. The recorded runs used Python 3.13.5,
PyTorch 2.x, NumPy, SciPy 1.15 and Matplotlib on CPU in float64.

```
python -m venv .venv
. .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Pandoc and a TeX distribution are needed only if you want to rebuild the Word
and PDF manuscripts. The numerical experiments do not need them.

The code repository is https://github.com/qiantanzhijiao/TMM-DD-Codesign.

## Reproduce

```
python experiments/experiments_final.py            # E0-E4, about 25 min, one CPU core
python experiments/experiments_supplement.py       # mesh convergence, budget analysis
python experiments/experiments_E4_highdim.py       # 16-D pre-specified supplement
python experiments/experiments_E4_factorial.py     # one-factor 8-D vs 16-D control
python experiments/experiments_baselines.py        # multi-start, noisy, extra baselines
python experiments/experiments_optics_ablation.py  # coherent vs single-pass optics
python experiments/experiments_mesh_N97.py         # mesh-upgrade assessment only
python experiments/experiments_optical_inverse.py  # model misspecification in thickness inversion
python experiments/experiments_adjoint_scaling.py  # dense-adjoint cost vs DD mesh N
python experiments/experiments_fd_baseline.py      # finite-difference gradients, same L-BFGS
python experiments/verify_scaps_official_examples.py --scaps-dir "<SCAPS install dir>"
python experiments/experiments_crosscode_fit.py    # external-target fit; renders via a child process
pytest -q tests/

# SCAPS-1D 3.3.12 cross-check (Windows). The runtime installer downloads the
# official UGent package, verifies its SHA-256 and deploys it privately next
# to the executable: no administrator rights and no system changes.
python experiments/install_scaps_runtime.py --check
python experiments/build_scaps_inputs.py
python experiments/run_scaps_crosscheck.py --scaps-dir "<SCAPS install dir>"
```

The files under `scaps_run/export/` are genuine SCAPS 3.3.12 outputs. Their
headers carry the installation path of the machine that produced them; this
is SCAPS-generated run metadata, not a code dependency. Every number quoted
in the papers is in the parsed CSVs and `acceptance_verdict.json`.

All experiments fix `seed = 0` and use float64 / complex128. The result files
are written incrementally. The older scripts and result files from 2026-11-06
are not included: their generation-rate formula, convergence test and
evaluation counter were superseded and must not be cited.

The active manuscript checker is `python paper/verify_variants.py`, which
validates both journal packages (223/223 checks) against the recorded results.
`scripts/check_consistency.py` is the archived v1 checker (161/161 on the
original Solar Energy draft); it exits with code 2 instead of reporting
spurious failures against the current v2 packages.

## What the results do and do not show

The validation is numerical and external where possible: optical energy
balance, the Beer-Lambert and incoherent limits, high-order finite differences
against automatic derivatives, adjoint residuals, dark-current and EQE/J-V
consistency, and a grid-convergence study with Richardson extrapolation.

The inverse-design targets are generated by the same forward model. They
establish that the gradients and the optimisation machinery are correct, not
that device parameters can be identified from measured data. No experimental
calibration and no efficiency record are claimed. An independent comparison
with SCAPS-1D 3.3.12 was executed with acceptance criteria fixed before the
run; two of four criteria pass, so it is a limited cross-code sanity check
rather than a validation. The pre-specified tenfold evaluation-count target
was **not met** in
three or eight dimensions; the 16-D supplement meets it only as a censored
lower bound, with a measured maximum of 8.57x at the loosest informative
threshold. Both negative results are reported in the papers.

Two further supplements are shipped as independent, pre-specified evidence:
E4-C varies only the number of free design variables (8-D versus 16-D, with the
8-D arm an exact linear subspace of the 16-D one), and E5 adds multiple starts,
1% relative observation noise and five derivative-free baselines. Their recorded
histories are in `results/results_E4_factorial.json` and
`results/results_baselines.json`; `docs/补充实验结果与因果解释.md` explains what
they do and do not establish. Where a derivative-free run stops before the
target loss, the reported ratio is a censored lower bound, never a measured
speedup. Neither supplement changes the E4 verdict or the E4-H censored PASS.

An optical-coherence ablation is reported in both manuscripts: replacing the
coherent field by a single-pass profile changes the reference-device Jsc by
0.0071% but the thickness gradient by 1.91%; over a 15-point grid the largest
gradient difference is 39.85% in thin, strongly absorbing stacks. The recorded
values are in `results/results_optics_ablation.json`, produced by
`experiments/experiments_optics_ablation.py`. Coherent optics is therefore
reported as consequential for inverse-design gradients, not as a generally
necessary correction to the current.

Three further synthetic experiments are shipped from the q/1109 review round.
`experiments_optical_inverse.py` changes only the optical generation model
inside a one-parameter thickness inversion and records a measurable thickness
bias together with a changed loss gradient; re-evaluated with the coherent
truth model, the misspecified design gives a slightly HIGHER Jsc, so the papers
explicitly state that the parameter bias does not translate into a current
penalty at that operating point. `experiments_adjoint_scaling.py` times the
forward solve, the forward-plus-adjoint solve and the isolated dense
transposed solve for N = 49, 73, 97, 121 and 145; the end-to-end cost is
dominated by the Newton iteration at these grid sizes, and a sparse or
matrix-free adjoint is listed as future work. `experiments_fd_baseline.py`
reruns the recorded three-dimensional E4 case with central finite differences
driving the same L-BFGS, charging both arms in forward-solve equivalents.
None of these changes the E4 `not met` verdict, the 16-D censored lower bound
or the 2/4 SCAPS outcome, and none is an experimental validation. The
item-by-item reviewer reconciliation and the physical-validation roadmap are
internal working documents and are deliberately NOT shipped in this
repository.

Two further checks concern the SCAPS side of the comparison.
`verify_scaps_official_examples.py` runs the three official example definition
files shipped with SCAPS 3.3.12 (CdTe, CIGS, Si) through the same headless
script chain and verifies pre-specified sanity, genuine 3.3.12 provenance and
run-to-run determinism (19/19 checks). `scaps_run/official_examples/` holds
the native `.iv`/`.qe` exports, the exact scripts, the curves and the
machine-readable verdict. This is an installation audit of SCAPS itself, NOT
a validation of UniDD and NOT measured data; the official `measurements/`
files distributed with SCAPS are simulation outputs, as their own headers
state, and are never treated as measurements here.
`experiments_crosscode_fit.py` replaces the self-generated inverse-problem
target with EQE and Jsc observables produced by SCAPS 3.3.12, using the same
IFT gradients and L-BFGS as E3/E4. The fit reduces the weighted residual from
1.68e-2 to 6.41e-3 and the EQE RMSE from 0.0937 to 0.0721, but returns
strongly biased parameters (d 29%, k 30%, tau about three orders of
magnitude) while the Jsc error slightly increases. That is the signature of
cross-code model mismatch, not a parameter recovery. See
`results/results_crosscode_fit.json` and `scaps_run/crosscode_fit/`.
This is a synthetic cross-code exercise with an external target, NOT
calibration against a measured device. Neither check changes any recorded
verdict or any claim in the manuscripts.

The executable SCAPS-1D chain, the parameter alignment table, the real
outputs and the acceptance verdict are in `scaps_run/`; the protocol, the
private run-time deployment and the per-item verdict are documented in
`docs/SCAPS1D交叉验证方案.md` and `docs/交叉验证数据核查报告.md`.
